# Independent Windows 10 Community installer and device pairing lab (2026-09-22)

The public Community source at commit `34c7e08` was checked out **independently** on a separate Windows 10 Pro test workstation where the official, paired YourHand Agent remained running. The test used locally compiled Community executables, synthetic `test.invalid` users, temporary SQLite storage, a loopback-only Core and new per-device signing keys. No real Google credentials, hosted services, customer accounts or production devices were used. The Agent source was amended **only** to permit insecure HTTP enrollment when the target is *exactly* `127.0.0.1` or `localhost`; all non-loopback enrollment still requires HTTPS.

## Executed results

**19/19 installation and connection checks passed:** clean public clone; `npm ci`; unit, source and privacy checks; native-helper build and guarded native tests; C# Windows GUI manager build; an unsigned test-only ZIP and per-session compiled Windows Setup download; actual Setup launch under the test user's Windows account; independent `%LOCALAPPDATA%/YourHandCommunity` installation, auto-start registry entries and manager GUI; bootstrap consumption and local Core pairing; installed Agent connected with its own newly generated Ed25519 device identity; authenticated read-only device ping; rejection of unauthenticated and unrelated synthetic users. The official `%LOCALAPPDATA%/YourHand` directory and pairing keys did not change.

The test owner revoked the disposable device from the local Core. **16/16 cleanup checks passed:** the Community uninstaller removed its own files and start/uninstall registry entries; the isolated Core was stopped and all three loopback ports were closed; the official YourHand Agent continued running, with all six monitored official files and original startup entry unchanged. Full local evidence and unsigned lab artifacts were retained only in the test workstation's **private Documents lab directory**, not published in this repository.

## Release boundaries and open acceptance work

This is evidence of an **actual independent Windows setup/Agent/GUI/pairing/uninstall path** under controlled synthetic conditions, not a production-certified release. The public repo does not include downloadable signed installers, a bundled and reproducibly signed Agent runtime, a standalone public HTTPS domain or ready-to-use Google OAuth credentials. Real Google sign-in/consent and an external network client's installation were **not** tested. A complete UI interaction and Windows UAC/lock-screen test, offline rollback and production-upgrade testing still need separate acceptance. The temporary unsigned installer and device keys are **not** for public distribution.

The original public source failed local pairing because it required HTTPS even for a loopback-only, self-hosted Core. The corresponding [enrollment URL validation fix](../src/multiuser/enrollment-url.mjs) must pass CI and the required CLA/rights-review gates before the test result may be represented as a test of the exact unmodified published source.
